# Audit Evidence Package

## What auditors need

| Element | Requirement |
|---|---|
| Control mapping | Which control and requirement this evidence supports |
| Population | Complete list for the period (e.g., all terminations Jan–Jun), with how it was generated |
| Completeness & accuracy (IPE) | Query/report parameters, system name, run date/time, row count, who ran it; ideally a screenshot of the query/filter |
| Sample | Auditor-selected or random sample with selection method (`control-testing-sampling`) |
| Operating evidence | For each sample item: ticket, approval, timestamp, system state proving the control operated |
| Period coverage | Dates align with audit period (Type II: whole period) |
| Integrity | Original exports (CSV/JSON) with hash, not edited spreadsheets |

## Good screenshots

Show system name/URL, logged-in user, date/time (taskbar clock or system timestamp), filters applied, and the relevant setting/value. Prefer exports or API output with metadata over screenshots where possible.

## Example: "Terminated users removed within 1 business day"

1. HR system termination report for the period (population) — report name, parameters, run time, count.
2. Sample of 25 terminations.
3. For each: termination date/time (HR), account disable time (IdP audit log `user.lifecycle.deactivate` / Entra `Disable account`), delta.
4. Exceptions explained with remediation.

## Automation

Collect recurring evidence via scripts/APIs on a schedule (IdP MFA reports, cloud config snapshots, vulnerability SLA reports), store immutably with timestamps — reduces audit scramble (`continuous-control-monitoring`).

## Output

`Request ID | Control | Evidence item | Source system | Generated by/when | Population size | Sample | Result | File (hash)`
